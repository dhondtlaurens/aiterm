AiTerm Design System

Swift is the source of truth. The system is the code in app/Sources/AiTermUI/ and the rules in its README.md. There is no generated token file, no canvas and no build step.

This page is a human view of that code, synced on request by the design-system skill. When the two disagree, the Swift wins — and you never need this page to write correct Swift.

  1. Reuse before new. A new variant or content case on an existing primitive. Badge absorbed three bespoke types this way.
  2. A pattern — existing primitives arranged. It keeps an AiTerm name and lives in Views/, not in the library.
  3. A genuinely new primitive. It owes a standard name, every measurement from Metrics, every colour from Palette, a declared variant × state matrix, a line in the README's inventory, and a test under app/Tests/AiTermUITests/.

Colour

Almost every token names an AppKit semantic colour rather than a number. .labelColor already knows what secondary text should look like under increased contrast, and it keeps knowing when macOS changes its mind; a literal does not. The deliberate exceptions are codeBackground — AppKit's text background resolves too close to the window background in dark — onAccent, the one solid white, which ink on the accent and the vendor discs' paper alias; markInk, the vendor discs' black; spinnerTrack; and the washes, which are alphas painted over another colour, something AppKit publishes no semantic name for. A colour derived from another — a wash, a dimmed ink, a pressed state — is a named member too, never an .opacity(…) written in a view.

One more rule, enforced by PaletteDistinctionTests: every distinctly-written token must resolve to a distinct colour. Where two roles share a value it is declared as an alias in the source, and shown as one here. The test exists because a hover wash once resolved to the surface it was painted over and drew a visible halo around every hovered avatar.

These hexes are resolved values, not definitions. Each one was read back from the live Palette under a forced .darkAqua appearance — the same resolution ColorProbe uses in the tests. The Swift names the semantic colour; macOS decides the number. Two of them follow the accent chosen in System Settings (.controlAccentColor and .selectedContentBackgroundColor) and are shown here at the default blue.

Scale

Every number on this page is a size at ×1. It becomes points where a view reads it, at the environment's InterfaceScale — @Environment(\.interfaceScale), set with .interfaceScale(_:), like Surface. Typography scales by itself, because View.font(TypeStyle) reads the environment, and is not rounded, so text never outgrows the layout around it. Space, Radius and Size are read through scale(…) and land on whole points; at ×1 that is the identity. Strokes — hairlines, borders, rings, the focus ring — do not scale. A size: parameter is points on screen: the caller scales the token it passes, and a view scales only its own token reads.

One theme

AiTerm is dark-only. There is no light variant to keep in sync, and this page commits to the same single theme rather than inventing one the app does not have. Kerning and shadow geometry — blur radius, offset, opacity — are deliberately not tokenised: they are one-off optical corrections on a single element, not a scale anything else draws from. Their absence from Metrics is a decision, not an oversight.

States are a matrix

A component's states are declared up front, not discovered: default, hover, pressed, disabled, focused, selected. A new primitive owes that matrix the same way it owes a name — every variant crossed with every state, decided before the first call site, rather than a hover wash bolted on the week someone notices it is missing.

One rule overrides the matrix: when a target does not exist, the control is absent, not disabled. SidebarView draws no VS Code badge when VS Code is not installed, rather than a greyed one — the branch after it stays on the row as plain text. A disabled control is a promise that the action exists and is currently unavailable — if it can never become available, showing it is a lie the user has to test by clicking.

Reduce Motion is honoured rather than ignored: StatusMark keeps its arc and drops the rotation.

Primitives

Twelve components, all in app/Sources/AiTermUI/. They take standard names and no AiTerm type appears in their signature — a primitive that knows what a task is has stopped being a primitive. Each one reads its ground from Surface rather than taking a selected flag.

Every variant below is drawn in HTML at the real numbers from Metrics. Where macOS draws something this page cannot — an SF Symbol, an NSPopUpButton's bezel — the card says so instead of pretending.

Badge

AiTermUI/Badge.swift

The one chip. 16 pt tall (Size.chip) at Radius.chip, labelled in Typography.monoChip, on a neutral wash from the surface it sits on. It replaced three bespoke types — EditorBadge, JiraChip and BranchLabelView's +n chip — that each redrew the same shape. Passing an action makes it a button; without one it draws its shape only. An optional iconTint inks the icon off the accent — a Settings check's green checkmark or amber warning — and yields to white on it like everything else. An optional diff (Badge.Diff(added:removed:)) extends it with signed line counts after its icon and label — +12 −3, green and red, Space.hairline apart, a true minus sign — and leaves out a side that is zero; an empty diff draws nothing extra. An optional suffix (Badge.Suffix(icon:text:)) closes the badge with an icon and a short text, Space.hairline apart and both in the label's ink — a merge request's resolved review threads, a bubble and 2/5; a badge that is only an icon and a suffix is drawn with both. A badge is a chip at its own width, never squeezed or stretched by the row around it. style: .quiet drops the box at rest: no outer padding, the label in the surface's secondaryInk, and the hovered wash drawn Space.tight outside the content so nothing moves; its content shape keeps the gaps between mark and diff clickable. The sidebar's project headers and task and terminal rows use it; everywhere else a badge stays .boxed. Passing menu in place of action makes it open a menu — a project header's +n of Jira projects — the same chip with the same hover, and accessibilityLabel says what a bare count cannot. Every token it reads goes through scale.

Icon

AiTermUI/IconSource.swift

Draws an IconSource at a size, optionally overriding its ink. IconSource is the one way to name any mark AiTerm draws — .symbol(String) for an SF Symbol, .brand(Brand) for a single-colour vendor mark, or .artwork(svg:fallback:) for a full-colour SVG that carries its own fallback (.gitlabTanuki, .piBadge) — so a component showing an icon does not care which kind it is. A brand or an artwork fills a size square; a symbol keeps its glyph's own width at that point size. The vendor paths live in Logos and are drawn by LogoGlyph, both internal to the module: the one way the app draws a logo, and no fill travels as a hex string.

The Operator

One Operator and one broadcast at a time. The broadcast runs a sprint's tickets: the Operator plans, starts the tasks, steers its agents and answers them from the brief and the code, and AiTerm does every write it asks for, gated by the slices frozen in the broadcast. Everything it says is one OperatorBadge; anything amber is yours. Two Metrics members came with it, Size.inlineMark and Sheet.boardWidth; no Palette member: the needs-you badge and a card's amber edge reuse statusChipAttentionFill and statusChipAttentionStroke.

OperatorHeading, BroadcastHeaderRow and OperatorRowView

OperatorHeading is a SidebarHeading above PROJECTS, on its anatomy. With no broadcast it is the heading and its "+" (an AddMenu with New Broadcast…), the one way to start one; there is no File menu item. While a broadcast exists the "+" is absent and the broadcast’s group sits under the heading (BroadcastSection), its own section of the sidebar, drawn by SidebarView.operatorRows above the projects: its header, the Operator’s row, then every task the broadcast holds, moved out of its project, in the plan’s order, the queued ones last.

The header (BroadcastHeaderRow, a BroadcastRow value) is a project header’s anatomy at Size.projectRow in a RowPill: HeaderChevron, the broadcast’s glyph, dot.radiowaves.left.and.right, in a ProviderIcon (its IconSource init) where a project has its host, the name in HeaderTitle, and Space.gap after it its progress, 2 of 8 (paused · 2 of 8 while paused, nothing until the first plan is in Todo), in Typography.monoChip and the surface’s secondary ink; then, in the trailing slot where a project has its "+", the board button, rectangle.split.3x1 drawn as the "+" is. Folded, it says what needs you in the group once, as an amber StatusCountChips count, and nothing else of what it hides; that chip’s click opens the group and selects the first row that needs you. Its tooltip is its projects over its whole status line (OperatorLine.broadcast, as the board’s band says it), which VoiceOver reads as its value; VoiceOver has the fold as its default action and the menu’s items, Open Board first, as named ones.

The Operator’s row (OperatorRowView, an OperatorRow value) is always first under it: a full Size.row SelectableRow, washed at rest in Palette.operatorRow and Palette.badgeHovered hovered, in RowPill’s pill, which selection replaces (Surface.washed, .washedHover). Proposal · Operator sheet · 21 Oct 2026

The board becomes a sheet with three tabs

Today the board is 820 pt wide, wider than every other sheet. Once every task is done the debrief takes the board’s place: Delivered beside three lists, Decided on its own, Found along the way and Left for you, so how the broadcast went has to be pieced together from fragments. And nothing records what the Operator did step by step, so when a broadcast goes wrong there is no trail outside its own conversation.

Proposed: the sheet at Sheet.width by Sheet.height, like Settings. The header keeps the title, the band and the Asked line, and gains a tab bar under them, the same SegmentedControl in its accent style that Settings uses: Board · Activity · Summary. Summary is dimmed until the broadcast is complete, and the sheet opens on it from then on; before that it opens on Board. The footer is unchanged.

Decision 1 · the board at 560 pt

Board

A

Lanes stacked, one list

Recommended

Todo, In progress, Review and Done one under another, each its SidebarHeading and count over its tasks, the whole tab scrolling as one. A task is a full-width row: its mark, the title on one line with the quiet Jira and MR badges at its end, then its status badge and project. A needs-you task keeps its attention edge; a click opens what it opens today. Everything is readable without scrolling sideways.

Decision 2 · what Activity lists

Activity

A new log, saved with the broadcast: every call the Operator made, with its time, its task and how it ended, refusals included, newest first. One line each in plain words; a line with a reason has it under it. Click a line for the call itself, its tool, its arguments and its result in mono, for debugging. It needs AiTerm to start recording; broadcasts before this have an empty Activity.

A

Everything, reads muted

Recommended

Every call, including what it only read (a diff, a Jira search, the run’s status) in muted ink, so you can see what a decision was based on.

B

Only what changed something

Reads left out: started, told, marked, merged, asked, decided and refused. Shorter, but a decision’s evidence is gone.

Decision 3 · the end report

Replaces the debrief.
