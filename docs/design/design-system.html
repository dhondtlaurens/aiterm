AiTerm Design System

Swift is the source of truth. The system is the code in app/Sources/AiTermUI/ and the rules in its README.md. There is no generated token file, no canvas and no build step.

This page is a human view of that code, synced on request by the design-system skill. When the two disagree, the Swift wins — and you never need this page to write correct Swift.

  1. Reuse before new. A new variant or content case on an existing primitive. Badge absorbed three bespoke types this way.
  2. A pattern — existing primitives arranged. It keeps an AiTerm name and lives in Views/, not in the library.
  3. A genuinely new primitive. It owes a standard name, every measurement from Metrics, every colour from Palette, a declared variant × state matrix, a line in the README's inventory, and a test under app/Tests/AiTermUITests/.

Colour

Almost every token names an AppKit semantic colour rather than a number. .labelColor already knows what secondary text should look like under increased contrast, and it keeps knowing when macOS changes its mind; a literal does not. The deliberate exceptions are codeBackground — AppKit's text background resolves too close to the window background in dark — onAccent, the one solid white, which ink on the accent and the vendor discs' paper alias; markInk, the vendor discs' black; spinnerTrack; and the washes, which are alphas painted over another colour, something AppKit publishes no semantic name for. A colour derived from another — a wash, a dimmed ink, a pressed state — is a named member too, never an .opacity(…) written in a view.

One more rule, enforced by PaletteDistinctionTests: every distinctly-written token must resolve to a distinct colour. Where two roles share a value it is declared as an alias in the source, and shown as one here. The test exists because a hover wash once resolved to the surface it was painted over and drew a visible halo around every hovered avatar.

These hexes are resolved values, not definitions. Each one was read back from the live Palette under a forced .darkAqua appearance — the same resolution ColorProbe uses in the tests. The Swift names the semantic colour; macOS decides the number. Two of them follow the accent chosen in System Settings (.controlAccentColor and .selectedContentBackgroundColor) and are shown here at the default blue.

Surface

A component reads the ground it sits on from the environment — @Environment(\.surface), set with .surface(_:) — instead of taking a selected: Bool. Each case publishes its own ink, secondary ink, badge wash, hovered badge wash and occluding background, so a badge inside a newly selected row turns white by itself rather than every call site re-deriving the same colours. Surface is not a component and gets no card; it is a rule the components assume.

Scale

Every number on this page is a size at ×1. It becomes points where a view reads it, at the environment's InterfaceScale — @Environment(\.interfaceScale), set with .interfaceScale(_:), like Surface. Typography scales by itself, because View.font(TypeStyle) reads the environment, and is not rounded, so text never outgrows the layout around it. Space, Radius and Size are read through scale(…) and land on whole points; at ×1 that is the identity. Strokes — hairlines, borders, rings, the focus ring — do not scale. A size: parameter is points on screen: the caller scales the token it passes, and a view scales only its own token reads.

Typography

The macOS system text scale. AiTerm draws with .system(size:) rather than a text style, so each member is labelled below with the system style it is the size of. One theme

AiTerm is dark-only. There is no light variant to keep in sync, and this page commits to the same single theme rather than inventing one the app does not have. Kerning and shadow geometry — blur radius, offset, opacity — are deliberately not tokenised: they are one-off optical corrections on a single element, not a scale anything else draws from. Their absence from Metrics is a decision, not an oversight.

States are a matrix

A component's states are declared up front, not discovered: default, hover, pressed, disabled, focused, selected. A new primitive owes that matrix the same way it owes a name — every variant crossed with every state, decided before the first call site, rather than a hover wash bolted on the week someone notices it is missing.

One rule overrides the matrix: when a target does not exist, the control is absent, not disabled. SidebarView draws no VS Code badge when VS Code is not installed, rather than a greyed one — the branch after it stays on the row as plain text. A disabled control is a promise that the action exists and is currently unavailable — if it can never become available, showing it is a lie the user has to test by clicking.

Reduce Motion is honoured rather than ignored: StatusMark keeps its arc and drops the rotation.

Primitives

Eleven components, all in app/Sources/AiTermUI/. They take standard names and no AiTerm type appears in their signature — a primitive that knows what a task is has stopped being a primitive. Each one reads its ground from Surface rather than taking a selected flag.

Every variant below is drawn in HTML at the real numbers from Metrics. Where macOS draws something this page cannot — an SF Symbol, an NSPopUpButton's bezel — the card says so instead of pretending.

Badge

AiTermUI/Badge.swift

The one chip. 16 pt tall (Size.chip) at Radius.chip, labelled in Typography.monoChip, on a neutral wash from the surface it sits on. It replaced three bespoke types — EditorBadge, JiraChip and BranchLabelView's +n chip — that each redrew the same shape. Passing an action makes it a button; without one it draws its shape only. An optional iconTint inks the icon off the accent — a Settings check's green checkmark or amber warning — and yields to white on it like everything else. An optional diff (Badge.Diff(added:removed:)) extends it with signed line counts after its icon and label — +12 −3, green and red, Space.hairline apart, a true minus sign — and leaves out a side that is zero; an empty diff draws nothing extra. A badge is a chip at its own width, never squeezed or stretched by the row around it. style: .quiet drops the box at rest: no outer padding, the label in the surface's secondaryInk, and the hovered wash drawn Space.tight outside the content so nothing moves; its content shape keeps the gaps between mark and diff clickable. The sidebar's project headers and task and terminal rows use it; everywhere else a badge stays .boxed. Every token it reads goes through scale.

Icon

AiTermUI/IconSource.swift

Draws an IconSource at a size, optionally overriding its ink. IconSource is the one way to name any mark AiTerm draws — .symbol(String) for an SF Symbol, .brand(Brand) for a single-colour vendor mark, or .artwork(svg:fallback:) for a full-colour SVG that carries its own fallback (.gitlabTanuki, .piBadge) — so a component showing an icon does not care which kind it is. A brand or an artwork fills a size square; a symbol keeps its glyph's own width at that point size. A brand keeps its vendor colour unless tint overrides it, which is what a selected row does: a brand colour on the accent reads as a mistake. A symbol with no tint takes the ink of the surface it sits on; an artwork has no one colour, so a tint reaches only its fallback. The vendor paths live in Logos and are drawn by LogoGlyph, both internal to the module: the one way the app draws a logo, and no fill travels as a hex string.

How this tab works

Nothing on this tab is in the code yet. A proposal is a change drawn at real size from the current tokens, with its options side by side, so it can be chosen before any Swift is written. Foundations and Components describe what ships; this tab describes what might.

Proposal · Backpack Mode, round 2 · 4 Oct 2026

Backpack Mode: the header glyph and Settings › Backpack

Round 1 shipped on the branch (a Backpack tab, a glyph while on). Trying it found three things to change before it merges.

  1. Nothing shows that ⌘B is working. Joining a hotspot takes seconds, and the sidebar stays still until it is done.
  2. A glyph that appears only while on cannot be found while off. It should always be there, as the + is, and say the state by its colour.
  3. The Settings card mixes setup, fields and status in one box. Two permissions, a network and a battery limit read as one list with no order.

Decision 1: the glyph, always there Picked: A

The backpack sits beside + in every state. Off is the +'s own grey (Palette.muted); turning on or off is StatusMark's spinner at Size.statusMark; on is Palette.accent; needs you is Palette.amber (off the hotspot, or near the battery limit). It updates within 5 s.

A

A click opens its menu, as + does

Recommended

The state in one line, then Turn On / Turn Off Backpack Mode ⌘B and Backpack Settings…. The two header glyphs behave alike, and the menu teaches ⌘B. While setup is missing, the first item is Backpack Settings… instead.

B

A click toggles; the menu is on a right-click

One click instead of two. But it is the only glyph in the sidebar that acts on a plain click without saying what it will do, and a stray click while dragging the window starts a Wi-Fi switch.

Decision 2: Settings › Backpack, in the other tabs' parts (2A, redrawn)

Picked: 2A, then redrawn in the vocabulary the other tabs already use, so nothing on this tab is new. Mac permissions is a harness card (Agents): a round mark, ✓ / ! check Badges beside the title, one action named by its state, and ItermSettingsCard's numbered steps only while something is missing. Hotspot is a service card (Jira, GitLab): fields side by side and the same "Save stores … in Keychain." line. Battery is a card too, with its own mark and the level as its status line, and a SegmentedControl as Sidebar size has. No step numbers: no other tab numbers its cards, and the order alone says which comes first.

Decision 3: the mode's glyph

Rendered by AiTerm itself (SF Symbols through Icon, at Size.trailingGlyph in the header and on a Size.control disc), not drawn by hand. Each row: the Settings mark, then the header off, on and needing you.

A

Backpack · backpack.fill

Recommended

Matches the name. Reads as “packed up, on the move”. Recommended: the name and the mark say the same thing.

B

Rolling suitcase · suitcase.rolling.fill

Travel, clearly. Would want the mode renamed (Travel Mode); a backpack name with a suitcase mark says two things.

C

Coffee cup · cup.and.saucer.fill

The macOS idiom for “stay awake” (caffeinate, Amphetamine). Says nothing about the hotspot or being away.

D

Laptop · laptopcomputer

The lid. Closest to what it does, but reads as “this Mac” and is the weakest at 10 pt.

E

Walking figure · figure.walk

Away from the desk. Thin at 10 pt; macOS uses it for fitness and accessibility.

F

Bag · bag.fill

A simpler backpack. Loses the straps that make it read as a backpack; looks like a shopping bag.

G

Mug · mug.fill

Coffee again, plainer. Same meaning as the cup, less recognisable.

H

Moon with Zs · moon.zzz.fill

Sleep. The opposite of what the mode does: listed only to rule it out.
