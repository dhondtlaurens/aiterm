# Review a pinned revision from New Review

## Goal

New Review runs the selected reviewer once and leaves its findings and the reviewed commit visible in the iTerm tab after the process exits. A blank prompt works on a machine without workflow plugins. The reviewer can trace the change into unchanged callers at that commit. The person can keep editing their checkout throughout the review.

## Where the launch changes

- **Existing owner.** `TaskLauncher.createReview` finds the task or review that owns the branch from Git's worktree listing. Its `openReview` calls `TaskWorkflow.reviewCommand`, which currently builds an ordinary interactive command with `AgentCommand.build`. Keep the owner check immediately before terminal delivery, the existing tab placement, the closed-window fallback and the row's ticket/MR attribution. Pin the commit while verifying that the worktree is on the requested branch. A branch switch during preparation must either preserve the originally verified input or give a visible refusal.
- **New review row.** Today `TaskWorkflow.createReview` passes `TaskCreator.createReview` to the shared `checkOut` helper and builds the same interactive command. Give the manual path a separate entry point that uses the existing checkout preparation, then builds the same one-shot request as the owner path. Keep the row and report a launch failure if preparation already made a real checkout. Existing review rows can still own their named branch, be archived, restored and removed.
- **Shared callers.** Unattended Signal reviews also call `TaskWorkflow.createReview`. Keep their entry point and ordinary task launches intact. Before editing, compare committed and working-tree changes in the concurrent workflow-agnostic worker branch, especially `TaskLauncher`, `AgentCommand`, the harness table, daemon tab creation and launch fixtures. The concurrent work owns Operator prompts, worker roles, helper routing and lifecycle.

## Review input and execution

1. **Pin the head at submission.** The launcher verifies the requested branch, reads the full commit ID from its owned or newly prepared checkout, and stages a small private request using that ID. Hold the owner/project creation slot only for the normal checkout and handoff. Start a command-line entry point of the bundled AiTerm executable in the review tab, before AppKit initialization. The tab receives only the shell-quoted executable and private request path. The helper claims the request atomically and immediately prints the reviewed branch and full head. It prepares the inputs in the tab before starting the vendor.
2. **Resolve the exact comparison.** Use the MR target when present and the detected project default for a branch-only review. With origin configured, ask origin for that branch's current ID. If origin is unreachable, report that the fresh target could not be verified and name the branch. A local-only repo can work offline. In a local-only branch review use the local default tip. Borrow the project's Git objects read-only via an alternate in a private bare repository. Keep the selected head reachable for preparation, including unpushed commits. If the advertised target and its ancestry are available, compute the merge base directly. When target history is missing, run Git's fetch in the project's configuration context and redirect the object destination into the private repository. Give this fetch the project objects as a read-only alternate. Request the target branch without a destination ref, clear the fetch refmap and suppress FETCH_HEAD, tags, pruning, submodule recursion, maintenance and commit-graph writes. This preserves Git's normal authentication and conditional includes. Verify the advertised target object and its history before using it; retry or report a changed target if needed. Handle shallow or incomplete history explicitly. Never write a target or scratch ref into the project. Print the effective target and merge-base IDs and use them and the pinned head for subsequent reads. If the trees are identical, report that the pinned range contains no changes.
3. **Prepare patch and committed files.** Generate the complete binary-capable patch between the two pinned trees, with external diff and text conversion disabled. Read Git output as raw bytes to a private file. Materialize the head's tree from objects into a source subdirectory. Preserve paths and bytes, including files with archive exclusion/substitution attributes. Represent symlink targets as data without following them into the person's files. Identify submodules by their recorded commit. Keep the Git object store and mutable bookkeeping outside the review workspace. The patch, source and context have separate paths. A size, path collision or materialization failure must identify the missing input.
4. **Launch once with the draft's choices.** Use the selected agent, model and effort. AiTerm's instruction asks for concrete findings with file and caller evidence, or an explicit clean verdict. Reference the patch and source directory and use the existing composition logic for the user's focus and independently enabled ticket and MR descriptions. Large inputs travel in files. Start the CLI in the private workspace. Use `HeadlessRun` for discovery, process-group execution and a manual-review timeout of 15 minutes. Reuse the harness's invocation and answer handling for Claude JSON, Codex's per-run answer file, PI stdout and Antigravity's final result.
5. **Constrain Antigravity's effective tools.** Create a fresh private workspace and a separate disposable Antigravity home outside any checkout. Supply the existing sign-in from the CLI’s file-backed credential or its scoped macOS Keychain item. Create the private credential with mode 0600 and direct the child’s token refresh, configuration, plugins, logs and temporary files into the disposable home. Put an AiTerm-authored main agent in its discovered workspace agent directory under a unique per-run name, select it with `--agent`, and preflight the exact definition. The source is an ordinary nested data directory. Pass only the private workspace as trusted, with no added workspace roots. Run one print turn with slash expansion disabled. The profile inherits the chosen model, disables inherited MCP and customizations, and lists only file viewing, search and listing tools. Exclude command execution, editing and subagent invocation. If this CLI cannot enforce the profile, report an unsupported reviewer. Verify discovery and effective tools with the installed version. A successful registry listing alone proves neither. [Antigravity agent discovery](https://antigravity.google/docs/cli/commands/agents) and [agent permissions](https://antigravity.google/docs/subagents?tab=cli).
6. **Validate the result before printing findings.** Inspect structured outcome and permission events before extracting a final answer. The current process runner retains only the first 4 MiB of each stream. Add a manual-review capture mode to drain stdout to a private file and consume complete vendor records incrementally with bounded memory. Enforce an explicit disk budget and surface overflow, an incomplete record or a missing terminal event as a failure. Keep the current in-memory path for existing callers. A final Codex answer file cannot override a dropped denial or failure event. Capture a real refused Antigravity action in the early capability check. Its stream's final result can carry `denied_actions`; check this alongside status and use its response for the existing answer extraction. If a supported CLI version omits denial evidence from that stream, verify a per-run log/trace or fail closed for that version. Capture real refused and successful runs for each supported vendor before writing its failure fixtures. For Claude, check `is_error` and actual entries in `permission_denials`, including a refused read. For Codex, record what a sandbox-blocked write emits in `exec --json`, including the command result, and compare it to an ordinary unsuccessful search. Classify explicit permission refusals and positively identified sandbox blocks as denied actions; an arbitrary nonzero shell command does not identify a denial. Use only observable vendor evidence before reading Codex's answer file. Verify the same distinction in PI print mode, using a structured output mode for manual reviews if required. A tool omitted from an allowlist has no action to report unless the vendor records an attempted call. When a required outcome cannot be distinguished on a CLI version, surface the unsupported capability. A denial takes precedence over a plausible answer. Exercise a missing CLI/profile, timeout, unsuccessful status, malformed or empty answer. Print a specific reason and return a failing exit status. Strip terminal control sequences when printing untrusted text. Return to the tab's shell after the command exits.
7. **Clean up on exit and interruption.** Run the vendor in its own session without a controlling terminal, with noninteractive stdin. Keep the helper in the foreground of the tab. Test that a child trying to open the terminal fails promptly. Bridge terminal interrupt, hangup and termination signals to task cancellation, then wait for `AgentProcess` to terminate the vendor process group before removing the patch, sources, request and answer. Remove an unclaimed request on definite delivery failure. After an ambiguous acknowledgement, allow a delayed tab to claim the request once. Reclaim stale unclaimed requests and abandoned scratch on a later launch, using a per-run lock to protect live work. When the command cannot be delivered at all, surface the sheet/row error, including `commandError` on tab creation and reopened windows. Keep a successfully created row.

## Git state

For an existing owner, compare the project from form submission through reviewer exit. For a new checkout, keep `Repository.addReviewWorktree` and its existing fetch, fast-forward, tracking-branch creation and divergence refusal. Record any expected preparation effects, then compare state from the end of `TaskCreator.createReview` through exit. Store any additional target objects in the disposable repository. Review inputs never come from copied worktree includes, the index or dirty files. Later removal of the review row follows its existing branch-release rules.

## Implementation evidence

- With Antigravity CLI 1.5.18, the native `read_file` can search committed files. The CLI also exposes `manage_task` when an agent requests only the reader. The generated agent attaches its own pre-tool hook and disables inherited customizations and MCP. The CLI runs in its own disposable home. The only personal file staged there is its sign-in, read from the CLI credential file or its specific macOS Keychain item. Its child environment omits personal config and plugin overrides. The hook accepts reads of the patch, manifest, optional context and pinned source. A live denied action appeared in a step event even when the CLI returned a successful final status. AiTerm checks both. Other CLI versions require verification before AiTerm will launch this profile.
- A live agent selection check placed two definitions with the same name in the workspace and its nested source. Antigravity followed the workspace definition. After its removal the CLI exited with an unknown-agent error.
- Both manual entry points submitted the branch-built helper to the daemon boundary.
