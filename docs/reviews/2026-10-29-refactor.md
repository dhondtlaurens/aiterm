journey tracing and targeted deep reads. This is not a claim that every unchanged line or every
possible test permutation received an independent manual review. The [suite index](2026-10-29-suites.tsv) maps each test file to its requirement area and named cases; passing tests are evidence of
those stated guarantees, not proof of all behavior.

## Test consolidation

Removed historical Operator-format/default/end/reviewer tests with their retired paths. Complete
current briefs, the 32-tool schema and the synthetic status/reply journey replace repeated prose,
punctuation and obsolete word bans. Removed the folder scanner, historical preference-cleanup test, obsolete status-line mode cases,
arbitrary sentence/punctuation limits and old eval fixtures; current eval setup/grading remains. Real transport forwarding, ownership,
Git/host safety, current no-goal behavior, reviews/fix rounds and extra-tab tests remain.

Important surviving coverage has a distinct purpose:

- Pure Core rules cover meaningful alternatives; app owner tests cover async ordering and wiring.
- Real temporary Git repositories prove branch/worktree effects and retry/adoption rather than
  repeating a mocked implementation.
- Frozen pre-refactor bytes protect current save/resume and model-facing behavior independently of
  the new encoder. They were never regenerated to make this change pass.
- Daemon wire fixtures and Swift decoders protect cross-language integration; the schema golden
  owns exact current tool descriptions. An isolated in-memory description mutation was detected,
  then the unchanged schema passed again. Generic schema validity and HTTP/RPC/replay tests remain.
- Native UI/design tests cover geometry, focus, scaling, appearance and module rules. Hidden-window
  and scratch-preference guards remain current requirements.
- The suite-name/source audit distinguishes redundant historical bans from useful negative safety
  checks. Exact Python AST test-body comparison found no remaining identical bodies; this alone
  does not establish semantic uniqueness.

## Independent review triage

Claude round 1 found a Critical switchover precondition: an unsupported historical broadcast would
block the strict workspace decoder. The user ended the current broadcast and removed the saved
broadcasts through the installed app. A subsequent read-only format count confirmed zero runs in
both primary and backup. No agent changed either file, and no legacy reader was added. Architecture
and release docs now state this precondition and the limit of an unsupported backup.

The Minor shutdown `open_tab` finding was pushed back: its launch intent is already durable;
`opening` preserves recoverable pending work for restart. Returning failed would misclassify that
intent. The stopped owner sends no new request. Round 2 accepted that reasoning and checked the docs/daemon
areas not fully read in round 1.

Round 2 settled both prior findings and confirmed the daemon's structural-registry ownership. It
found an Important snapshot activation-policy mismatch: hosted fixtures need windows, so debug
snapshot entry now uses accessory activation rather than prohibited, following
[AppKit's activation contract](https://developer.apple.com/documentation/appkit/nsapplication/activationpolicy-swift.enum).
Its Minor headless-review finding prompted removal of the remaining wake/hold/sidebar/publication
decision branches, activity and unused timeout. Saved evidence projections remain read-only data.
The deterministic eval fixture now uses review-tab verdicts instead of fabricated headless results.

One full pass exposed a different test issue: two fresh renders of the same disabled-goal fixture
produced different PNG bytes. The duplicated self-comparison checks had no approved baseline and
could not detect a consistent visual regression. They are consolidated into one fixture-render
check; round 3 restored its determinism/content guards with a narrowly intermittent native case.
Targeted geometry/appearance/dimming assertions and the actual README baseline check remain. No production visual rule or timeout changed to accommodate it.

Round 3 found no Critical or Important code defect. Its Minor render-test concern was adopted:
the shared smoke check again checks content size and repeated rendering, with only the disabled
goal fixture's pre-existing native-render variation labelled intermittent. Its separate dimming
assertions remain unconditional. The suite inventory is refreshed. Remaining dead review constants,
comments and the obsolete future-wake promise were removed; the Activity formatter keeps the
served tool's readable refusal wording. All three review rounds are triaged, with no open
Critical/Important finding. Final execution proof is green in the verification table above.

Hosted proof: `scripts/readme-picture.sh --check` passed with the accessory snapshot entry;
`docs/desktop.png` matches the checked-in baseline exactly. The renderer exited without the
product launch/shutdown path. The final focused pass passed 71 app cases across five suites and
21 Core brief cases, including current-format journey and all frozen brief variants.

## Integration with main

The refactor was rebased onto `9a465d37` after the user requested rebase and merge. Its newer
Operator heading/decode behavior and tests are retained. The only rebase conflict was the UI
README; its concise rules remain, with the current decode behavior documented in the app-pattern
guide. The suite index was refreshed against the combined source, including multiline tests.

The first integrated run exposed a readiness-test race: a partial not-ready response can arrive
before both agent probes finish. The test now waits for both planned card snapshots and the
policy read before asserting the final missing checks, without changing production behavior or
timeouts. Incidental EOF whitespace was removed; captured prompt bytes remain unchanged.
Full tests, hosted README comparison and a fresh release bundle are rerun before advancing main.
