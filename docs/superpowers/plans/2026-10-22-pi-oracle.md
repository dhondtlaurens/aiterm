# PI as the Oracle Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** PI can be the Oracle and an agent reviewer, headless and read-only, at its picked model and thinking level.

**Architecture:** Extend `ChallengeLaunch.invocation`/`critique` (which `AgentReview` reuses) with PI's case and
widen `FixerLaunch.modelWords` and `AgentIntegrations.fixerModel` from `FixerAgent` to `AgentKind`, so each agent
gets its own words and its own default model. Settings › Operator and `review_task` then accept every `AgentKind`.

**Tech Stack:** Swift 6.4 (swift-testing), Python daemon (pytest).

**Spec:** `docs/superpowers/specs/2026-10-22-pi-oracle-design.md`

## Global Constraints

- Build and test only through `scripts/swift.sh` / `scripts/test.sh`; never `swift` directly. Daemon: `daemon/.venv/bin/pytest` from `daemon/`.
- PI's run: `["-p", "--no-session", "--no-extensions", "--no-mcp", "--no-skills", "--no-prompt-templates", "--no-approve", "--offline", "--tools", "read,grep,find,ls"] + modelWords + ["--", prompt]`, executable `pi`, no answer file.
- `--thinking` only for a level in `PiModelCatalog.thinkingLevels`.
- Settings copy: no em dashes, curly apostrophes (’); Oracle help still ends "Changes apply to the next broadcast."

## Review Focus

- A prompt that starts with `-` (a diff line) must not be read as a PI option: it follows `--`. Test in Task 1.
- An Oracle saved with a Codex level PI doesn't name (e.g. a stale value): no `--thinking`, PI's default. Test in Task 1.
- An empty model (no card default, none remembered) passes no `--model` for PI, as for the others. Test in Task 1.
- A PI reviewer with no PI card default takes PI's remembered model, never Claude's. Test in Task 3.
- A saved PI Oracle with PI not installed is still shown, not swapped. Test in Task 2.
